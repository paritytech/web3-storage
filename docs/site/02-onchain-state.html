    Providers and agreements

    • • ProviderInfo also has endpoint (Physical multiaddr or Virtual), public_key, committed_bytes, last_stake_event, stats
    • • stake applies to new agreements; set_stake lowers it only while higher_stake_lock is not active, then the old figure stays locked until cur_until, the latest expiry struck under it
    • • lock_active(until, p) = now < until or p.pending_challenges > 0, for higher_stake_lock, higher_pps_lock and members' ProviderVirtuals entries
    • • role: Primary, or Replica { sync_balance, sync_price, min_sync_interval, last_sync: ReplicaSyncRecord { commitment, block }, last_sync_signers }
    • • pending_replacement: Option<PendingReplacement>; virtual_snapshot: Option<VirtualSnapshot> (members, per_provider_stake)
    • • AgreementNonces: AccountId → next expected terms.nonce; redemption advances it (NonceMismatch)

    Buckets

    • • Bucket also has visibility, frozen_start_seq, min_providers, historical_roots: [(u32, Commitment); 6]
    • • snapshot.primary_signers: bit i set if slot i signed; a virtual primary takes one slot per member
    • • NextBucketId allocates each BucketId(u64); Bucket.next_agreement_id each AgreementId(u32)

    Challenges

    • • Challenge: bucket_id, provider, challenger, agreement_id, snapshot (virtual), commitment, liable (virtual), kind, target, deposit, authorized, all recorded at creation; agreement_id, snapshot, commitment, liable and kind are copies, so the challenge needs no agreement record
    • • kind: Checkpoint, Offchain or Replica; Superseded is not a valid response to Replica
    • • Agreements and payments ignore open challenges: the agreement can settle, extend or be replaced while one is open
    • • Creation increments the challenged provider's pending_challenges (virtual: the synthetic account); defence, cancel_challenge or resolve_expired_challenge decrements it once
    • • Hold: deposit as ChallengeDeposit

    Virtual providers

    • • VirtualProviders: keyed by the synthetic account (PalletId + virtual id); stake = k × per_provider_stake
    • • ProviderVirtuals: read by set_stake and deregister_provider; a Leaving entry keeps stake_at_risk locked until its until block and while the virtual is challenged
